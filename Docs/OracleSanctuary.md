# Oracle sanctuary: room-specific architecture and persistent identity

Implemented 2026-11-03. This is the architectural/lighting phase of the agreed Oracle-level concept. NetHack still owns the level, doorways, visibility, monsters, statues, fountains, traps, movement and gameplay. The Oracle and centaur statues retain their current native/fallback presentations; bespoke Oracle/centaur sculpture is a separate art pass, not claimed complete here.

## Persistent identity

The native bridge emits `oracle_x`/`oracle_y` for the original Delphi chamber, or -1/-1 on other levels. It uses the game's saved Oracle special-level identity and the chamber's existing **orig_rtype**, not a monster search, fountain count, map-pattern guess, renderer cache or hard-coded depth. NetHack converts active `rtype` to OROOM after its welcome message; using `orig_rtype` is essential. The native save already persists this information, so no new save format or sidecar identity file is needed. Killing or moving the unique Oracle does not change the chamber's original identity.

The UE parser resets the anchor on clear/missing metadata and accepts each state's native anchor. The anchor is private presentation metadata, never a map-reveal instruction: only actual known native cells render. Rooms on other levels receive the original treatment. The architectural extent is the fixed 13x11 wall-inclusive rectangle around the original 3x3 Delphi chamber, matching pinned `upstream/NetHack/dat/oracle.lua` (outer floor 11x9). Native source generates eight historic centaur-class statues and the four fountains; the renderer never reconstructs them from those expected positions.

## Construction and integration

- Editable source: `Art/OracleSanctuary/OracleSanctuary.blend`, generated by `Scripts/CreateOracleSanctuary.py`.
- One double-sided wall module: pale limestone/marble, darker plinth, twenty-flute tapered columns, base/capital blocks, entablature and real bronze meander inlay. This is artistic interpretation, with no added gameplay symbolism.
- Actual wall mesh bounds: approximately x +/-0.49 m, y +/-0.48 m, z 0-1.20 m. All decoration stays within a native wall cell; wall height matches the existing 120 cm walls. No roof covers the sanctuary. There is no new collision or passage obstruction.
- Geometry: 51 editable mesh parts, 20,084 triangles. `ReviewOracleSanctuary.py` validates finite geometry, nonzero face areas, closed manifold parts, Paint attributes, bounds, no animation/pending modifiers, and all **232** prior FBX hashes unchanged (`inspection.json`, `protected.json`). LOD/performance finishing remains separate.
- Imported static mesh: `/Game/OracleSanctuary/Meshes/SM_oracle_wall`, with batch-local paint/bronze materials and normal/memory variants. `VerifyOracleAssets.py` reloads saved assets, confirms vertex colours, slots, material paths and saved packages. Source/rear/three-quarter and tiny images are actual Blender renders, not concept art.
- `DungeonOracle.cpp` places wall modules only on native displayed walls within the room. Orientation follows outer/inner wall locations. Native openings are left open, including the variable inner chamber entrance and outer corridor connections. Pale floor instances use the existing 8 cm floor surface; native features and entities then use their established paths.
- `DungeonAtmosphere.cpp` gives the sanctuary deliberately placed wall sconces directed toward adjacent visible, permanently lit floor. Visible, natively lit, uncovered fountains get a restrained cooler local light. Unknown walls emit no sconces; remembered geometry has its separate lighting/material channel; covered or drained fountains emit no fountain light. No native lighting flags, sight range or game RNG change.
- Strict topmost presentation is preserved: architecture receives the same topmost-filtered cells as ordinary terrain. A foreground covering a wall suppresses its module; covered fountains are not redrawn or illuminated. Neither statues nor monsters are spawned from the room template.
